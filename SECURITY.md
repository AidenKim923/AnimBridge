# Security policy

Security fixes are reviewed on the current development branch on a best-effort
basis. A successful build or a passing unit test does not establish full engine
compatibility. Supported platforms and known limitations are listed in the
[README](README.md).

## Reporting a vulnerability

Do not put exploit instructions, credentials, commercial animation assets,
project archives, or personal filesystem paths in a public issue.

Use GitHub's private vulnerability reporting for
[AidenKim923/AnimBridge](https://github.com/AidenKim923/AnimBridge/security)
when that option is available. If the repository does not offer a private
reporting channel, open an issue that only requests a private contact channel;
wait for the maintainer's response before sharing technical details.

Include the affected version or source revision, operating system and CPU,
the relevant workflow, expected and observed behavior, and a small synthetic
reproduction that you have permission to share. Remove secrets and personal
data from logs. Reports and fixes have no guaranteed response deadline.
